---
name: 第十九式：常量格式与调用方约定不一致 ⇒ 静默走兜底分支
description: 照抄相邻代码的常量但调用方传值格式不同（如 _MP4_FAMILY 漏前导点），会让分支判断恒为假、静默降级到兜底路径，症状是下游 rc=8/缺选项
type: feedback
---

2026-10-09 给 `convert_sdr_to_hdr.py` 加字幕透传时踩到：`_MP4_FAMILY` 被我照抄自
音频侧的同名常量（`{"mp4","m4v","mov"}`，**不带前导点**），但字幕侧的调用方传的是
`dst.suffix`（形如 `".mp4"`）。

⇒ `".mp4" in {"mp4", "m4v", "mov"}` **恒为 False** ⇒ 容器分派静默落到
「未知容器」兜底分支（返回 `None` = copy）⇒ **不下发 `-c:s`** ⇒
ffmpeg 报 `rc=8 Automatic encoder selection failed`。

**Why:** 这类失效没有任何报错、也不像拼写错误那么明显——常量本身**看起来完全
正确**，只有在「与调用方约定不一致」时才发作。症状出现在**下游**（ffmpeg 的
rc=8），离真正的病因（常量的点）隔了两层，导致我先怀疑了 `-map` 位置、
`-c:s` 语义、容器能力、ffmpeg bug 共四轮。
之所以音频侧那份不带点是**对的**：它收到的是已经 `normalize_container()` 过的值。
**同一个常量在两处语义不同，照抄必错。**

**How to apply:**
- 复用/照抄常量前，**必须确认调用方传进来的是什么形态**（带点？大小写？已归一化？
  绝对还是相对路径？）。同名不等于同契约。
- 容器/格式类分派函数里，**兜底分支不要静默返回"最保守的默认值"**——
  至少 warn 一句「未识别的容器 X，按 copy 处理」，让下游缺选项时能反查上来。
- ⚠ 判别这类问题的快速手法：**直接跑那个纯函数**，
  `resolve_xxx(".mp4", "mov_text")` 打印返回值，比跑整条转换快几个数量级。
  我是在全场景矩阵失败后回头单测这个函数，才一眼看出「全都返回 None」。
- 同族的其他「约定不一致」实例：`_BITMAP_SUBS` 里 codec 名必须**小写**（ffmpeg
  输出是小写）、`-map N:s:0` 的 N 是**字幕流内序号**而非全局 index。
- 关联 `feedback_malformed_container.md`（同为「下游报错、病因在上游」的排查法：
  先手工跑 ffmpeg 区分「工具行为」与「自己代码」）。
