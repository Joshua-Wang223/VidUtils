**规则**：`probe/loo_equal_quality.py` 的 LOO 判据口径 = **`GATE_ANCHORS = (0, 27)`**：
只有锚点 `crf∈[0,27]` 的 ΔVMAF 计入 FAIL；`crf>27`（现状仅 crf30）的 worst 作**「监控[全]」列
打印、不计 FAIL**。同轮门禁改为**分档**（软编/NVENC ≤5.9、rav1e ≤7.5；`--tol` 显式给出时覆盖）。
与 VE `Accessory/probe/eqq_pool_fit_table.py` 的 `GATE_ANCHORS`/`GATE` 同步。

**Why**（2026-10-04 全 8 档实测）：现状 worst **对每个编码器都发生在最高锚点 crf30**
（逐锚点跨素材最差 0.94 / 1.93 / 2.91 / 3.25 / **6.41**）——crf30 处各编码器质量曲线进入陡降段，
把小参数偏差放大成 5~6 dB，属**门禁给边界锚点同等权重**的系统偏差，非换算缺陷（曾被误当
「结构性上限」）。仓主确认**生产/CLI 的 `crf_ref` 基本不用 >27** ⇒ 判据覆盖工作区间即可，
监控列保证高 ref 段不被隐藏。（门禁数值 1.0 → 5.9 的先例见立项；本次是把**锚点口径**钉到
工作区间，不是再放宽阈值数字。）

**How to apply**：
- 跑 LOO 看 **`LOO[0,27]`** 判达标，**`监控[全]`** 仅观察；输出已分两层打印。
- ⚠ **前提若变（生产用到 ref>27）必须恢复全区间门禁或改稳健统计量，不得静默沿用。**
- 已排除的替代方案（VE 实测，均无改善）：加密扫描点 / 加素材 / 二次或幂模型 / 换 VMAF 轴 /
  内容类截距（仅备选）。
- 新口径 NVENC LOO[0,27]：h264 **2.77** / hevc **3.23** / av1 **2.79**（监控[全] 3.97/5.85/5.76）。
